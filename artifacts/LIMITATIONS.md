# VeriUnlearn — Limitations (Current Implementation)

**Date:** 2026-07-18 · **Target:** v1.0 RC
An honest account of what the current codebase does **not** yet do. Do not overstate
these in the IEEE paper or enterprise demo.

---

## 1. ML Engine not wired to real torch models in this environment
- `membership_inference.py` and the algorithm modules import `torch` and reference
  `models/single_model.py`, `models/sharded_classifier.py`, `training/data.py`, but the
  demo/benchmark run in this environment uses numpy/synthetic paths. Real model training
  and GPU unlearning have **not** been executed end-to-end here.
- `hybrid_controller.py:20-24` guards `torch` import; `CUDA_AVAILABLE` may be `False`.

## 2. Evaluation harness not yet executed for v1.0
- No v1.0 benchmark run has produced authoritative numbers. All figures in
  `demo/benchmark-reports/sample-report.json` are **demo/illustrative** and must be
  regenerated by `evaluation/run_all.py` before publication.
- Memory profiling on real models is pending.

## 3. Orphaned / unwired modules
- `packages/ml-engine/security/input_validator.py` — not invoked by API handlers.
- `packages/ml-engine/security/audit_logger.py` — not invoked by API handlers.
- `packages/ml-engine/verification/quality_metrics.py` (`QualityEvaluator`) — not called
  by the e2e pipeline, so benchmark-quality metrics (forget rate, MIA risk, inversion
  resistance) are not produced on real runs.

## 4. Single-tenant assumptions
- Although `MLEngineClient` carries `tenant_id`/`user_id`
  (`ml_engine.py:408-441` e2e, `record_conversation`), much of the model/store layer
  assumes a single tenant. Hard multi-tenant isolation (per-tenant models, quota,
  data residency) is not fully enforced.

## 5. Proxy connection handling
- `MLEngineClient` builds a new `httpx.AsyncClient` per call
  (`ml_engine.py:44` etc.); no connection pooling. Acceptable at RC scale, but a
  throughput limitation under load.

## 6. Contract coverage
- Not every Backend→ML Engine route is covered by an integration test; risk of silent
  drift (AUDIT C-4, TECHNICAL_DEBT D-4).

## 7. Benchmark dataset scope
- Demo report covers `cifar10/cifar100/tiny_imagenet`; the IEEE plan adds MNIST/IMDB/AG
  News but those runs are not done.

## 8. ZK claims
- zk-SNARK proofs exist in `verification/zksnark/` but are "ZK-adjacent"; do not claim
  full zero-knowledge deletion certification without validating the circuit.

See `artifacts/FUTURE_WORK.md` for how each item is planned to be addressed.
