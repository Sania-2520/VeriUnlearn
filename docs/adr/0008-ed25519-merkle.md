# ADR-0008: Ed25519 + SHA-256 Merkle for verification

- **Status:** Accepted (2026-02)

## Context

Deletion proofs must be tamper-evident and verifiable by third parties (auditors, regulators)
without trusting VeriUnlearn.

## Decision

- **SHA-256** for all artifact hashing and Merkle trees (`app.crypto.merkle`).
- **Ed25519** (PyNaCl) for signing certificates and proof roots (`app.crypto.signing`).
- API keys hashed with **SHA-384** and prefixed `vu_`.

## Consequences

- ✅ Small, fast, well-audited signatures; no PKI infrastructure needed.
- ✅ Merkle proofs allow batch verification and efficient inclusion checks.
- ❌ Not post-quantum (accepted risk; see ADR-0012 for ZKP direction).
- ❌ Ed25519 keys are single-tenant signing keys; key management lives in
  `SecretsManager` (Vault/env fallback).

## Alternatives considered

- RSA-4096 (supported in `signing.py` but slower; used only where required).
- ECDSA P-256 (rejected: Ed25519 simpler + safer implementations).
